# 複合問題的未答子題補查

2026-10-30。此變更是「逐子題取得證據後再生成」的開發版本，借用 SubQRAG 的證據不足補查、CRAG 的相關性把關與 ADD-RAG 的有上限重查概念；沒有移植其模型或訓練 PPO。

## 問題與實作範圍

原拆題流程在至少一個子題通過知識庫分級時，直接生成可答部分，其餘只補固定說明。2026-10-29 的 1,000 題配對實驗顯示需要網搜的需求覆蓋下降約 7.58 個百分點，因此先單獨驗證補查機制。

新開關開啟後，僅對「部分子題有 KB 證據」時其餘未通過的子題，執行一次既有白名單網頁檢索流程；沿用中英查詢與原有空結果重搜上限。檢索、分級使用保留相關病況與用藥條件的 `SubQuestion.question`。網頁資料必須通過同一個 CRAG 標準才能進生成；不將原本未通過的 KB 文件混入。

各缺證據子題可並行補查，每題預算包含查詢改寫、網搜與分級。補查失敗、未通過或逾時時保留其他子題的答案，並由程式列出未完成子題。原本全部子題皆無 KB 證據時，仍走整題原流程，以便隔離此次修改的效果。

KB 與通過的網頁證據交錯取用，共用既有 `rerank_top_n` 上限，再做一次統一生成、連結檢查與來源編號。沒有分到生成上下文名額的子題不列為可答。使用網頁證據時加網路資料前綴；不先各自生成再解析字串拼接來源，也不額外啟動知識回報。

## 開關與預算

```dotenv
RAG_COMPOUND_DECOMPOSE_ENABLED=true
RAG_WEB_FALLBACK_ENABLED=true
RAG_COMPOUND_WEB_FOLLOWUP_ENABLED=true
RAG_COMPOUND_WEB_FOLLOWUP_TIMEOUT_SECONDS=12
```

補查開關預設為 `false`，可獨立於拆題開關切換，便於對照與回復。每題補查預算必須大於零；整個回答仍受 `RAG_ANSWER_TIMEOUT_SECONDS` 限制。未修改拆題提示詞、至少兩個問號與 zh-TW 的前置規則；語意拆題判斷留待另一組實驗。

日誌保留 `rag_compound_web_followup` 階段、嘗試與通過數，成功使用網頁證據的總路徑為 `kb_compound_web`，不新增使用者問題原文日誌。

## 驗證與對照方式

單元測試涵蓋缺證據子題補查、未啟用及全 KB 可答時不補查、全域網搜開關、空結果／不相關文件、搜尋與分級失敗、單題及總回答逾時、取消傳遞、並行補查的局部失敗、共同上下文預算，以及合併後來源編號。網搜檢索入口另驗證白名單與不生成／不回報的契約。

三組開發實驗為原流程、既有拆題版、拆題＋補查版。後兩組控制相同拆題結果，保留相同模型、知識庫、上下文預算與總逾時；記錄新增檢索次數。主要觀察需求覆蓋與全需求回應率，另報需網搜需求、引用編號、延遲、失敗與人工抽查。

36 題開發試驗取既有題庫的 18 個原題家族及其改寫：單需求、全 KB 複合、KB／網搜混合各 12 題。按固定雜湊抽樣，不按過往答案好壞挑題。每個可拆題輸入先實際呼叫一次拆題模型，再於兩個處理組內重播相同結果與該次耗時，讓兩組總逾時都包含相同拆題成本；故延遲屬控制重播條件下的量測，不能當作兩次獨立線上拆題呼叫的估計。此為額外檢索預算的原生流程比較，尚非固定檢索呼叫數的公平預算實驗。

既有題目已被用於診斷，這輪不能當成新的盲測或臨床驗證；後續確認性實驗需新增盲測題與醫療專業複核。評分只測文字需求回應，不能當成醫療正確率。

實驗方案、執行程式與結果存放於工作區 `output/rag_compound_followup_20261030/`。實驗狀態以該目錄的紀錄為準，準備完成不代表已執行。
