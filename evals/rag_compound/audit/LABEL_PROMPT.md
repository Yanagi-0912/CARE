# 標註者指示（所有標註批次共用）

你是 CARE 健康助理評估題庫的標註者。請先完整讀規格 `SPEC.md`（和這份檔案在同一個資料夾）。

別人「不看知識庫」先寫好了題目（盲寫）。你的工作是去知識庫找答案，並定案類別。你負責的來源檔、行數範圍、輸出檔，寫在交派你的訊息裡。

**輸出檔可能已經有前一位標註者的部分成果**：先讀輸出檔，已經有的 wid 不要重做，從還沒做的接著做。

## 每一題怎麼做

1. **query 照抄。** 只有兩個例外：
   - 藥品中文商品名：用知識庫 `grep` 確認它確實是句中講的那類藥。查不到或對不上，就改成一般說法（例如「降血糖的針」「抗凝血藥」），並在最外層 notes 寫「原句商品名 X 無法確認，改成 Y」。
   - 題目明顯是「正在發生的急症求救」（例如人現在昏倒、正在大出血）：不要標，在最外層 notes 寫「急症求救，建議剔除」，category 照填，subquestions 留空陣列，expected_intents 填 0。只是問「這種症狀要看哪科／要不要急診」的一般問題要照常標。
2. **寫子問題**：以出題者的 asks 為起點，`ask` 只保留會改變答案的條件。每個子問題照規格做三種搜尋、`read` 全文確認，決定 route 與 expected_title_substrings，寫清楚 notes。
3. **以證據定案類別**（照規格）：
   - 出題者寫 true_compound，但需求其實被同一篇同一段一起回答 → 改成 single_need，合成一個子問題。
   - 出題者寫 single_need，但其實需要不同文章 → 改成 true_compound。
   - 改了就在最外層 notes 寫「出題者原判 X，改成 Y，因為…」。
4. **某個子問題能回答的文章超過 20 篇**：把 ask 改具體，或在 notes 標記。不要直接放棄整題。
5. **欄位**：`source` 填 `blind`，`golden_id` 填 null，`wid` 沿用原編號，`topic` 沿用。

## 寫檔規則

- **每標完一題就立刻追加一行**（`cat >> 檔案 <<'EOF'`），不要整檔覆寫。
- 工具與知識庫都是唯讀。需要小腳本就放在 `B_label/tmp_<批次代號>/`。
- 做完後跑 `python3 tools/validate.py <輸出檔> --detail` 自我檢查。
  - 有問題就修正那一行：用 python 讀整檔、改那一行、寫到暫存檔，再用 mv 取代原檔。不要弄丟其他行。
  - 急症剔除的那幾行，驗證會報子問題數的問題，屬正常。
- 確認輸出檔行數等於你負責的題數，而且 wid 不重複。

## 最後回報

- 兩類各幾題、改判類別幾題、改了商品名幾題、建議剔除幾題。
- 子問題 kb／web 各幾個。
- 特別不確定的題目（列 wid 與原因）。
