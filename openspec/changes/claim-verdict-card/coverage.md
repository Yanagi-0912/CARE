# 覆蓋率與門檻校準（tasks 1.1 / 1.2）

量測日期：2026-08-18。知識庫狀態：TFC 802 篇（判定覆蓋率 100%）、總計 9,182 chunks。

## 結論

| | |
|---|---|
| 覆蓋率（判定正確率） | **78%**（門檻 0.86，60 題） |
| 停止條件（< 30%）| **未觸發**，本 change continue |
| 誤配率（加同一性驗證前）| 65% |
| 誤配率（加同一性驗證後）| **10%** |

## 1.1 覆蓋率（正樣本）

30 篇 TFC 查核報告，每篇用 LLM 改寫成 2 句口語問句（共 60 題），打實際的
normalizer + matcher。

第一版用「配到的文章 URL 是否等於期望 URL」計分，得出命中率 70%、誤配率 16%。
**那個指標是錯的**——TFC 對同一則謠言常有多篇查核報告（新舊站都有），配到另一篇
同主題報告對使用者是正確答案：

```
Q: 聽說蛋洗了反而會讓細菌跑進去？
   期望 salmonella-risk-from-contaminated-eggs...
   實得 migration-9700  ← 也是講蛋與沙門氏菌的查核報告
```

改用規格定義（判定值是否相同）重算同一批資料：

| 門檻 | 有給判定 | 判定正確 | 判定錯誤 |
|---|---|---|---|
| 0.80 | 98% | 93% | 5% |
| 0.84 | 92% | 87% | 5% |
| **0.86** | 82% | **78%** | 3% |
| 0.88 | 65% | 65% | 0% |
| 0.90 | 50% | 50% | 0% |

門檻 0.86 的兩筆判定錯誤都是**相鄰等級**（期望「錯誤」、實得「部分錯誤」），
不是真假顛倒——使用者仍被告知該說法有問題。

## 1.2 門檻校準（負樣本）

正樣本只量得到召回。負樣本量的是「不該答的會不會亂答」，那才是 design 決策 3
說的嚴重失效模式。素材：8 則手寫的、TFC 未查核過的偏方 + 12 題 golden set 既有
的衛教型問句。

**加同一性驗證前**：

| 門檻 | 未查核謠言誤配 | 衛教問句誤配 | 合計 |
|---|---|---|---|
| 0.86 | 88% | 50% | 65% |
| 0.88 | 62% | 33% | 45% |
| 0.90 | 12% | 0% | 5% |
| 0.92 | 0% | 0% | 0% |

```
[0.918] 錯誤     網傳把洋蔥放在枕頭邊可以降血壓？   ← TFC 沒查過
[0.885] 錯誤     糖尿病可以吃水果嗎？             ← 衛教問句，不是查核
```

這些句子與查核報告在向量空間裡都是「食物與健康的網路傳言」，相似度分不開。
單靠拉高門檻可以壓到 0%（0.92），但正樣本只剩約三成過得了。

**加同一性驗證後**（design 決策 9，門檻維持 0.86）：

| | 前 | 後 |
|---|---|---|
| 未查核謠言誤配 | 88% | **12%** |
| 衛教問句誤配 | 50% | **8%** |
| 正樣本仍給判定 | — | **75%** |

殘餘的兩筆誤判：一則配到主題極近的報告（「某運動能否逆轉膝關節退化」），LLM
判為同一主張不算離譜；另一則「如何預防中風」是衛教問句被當成查核型，那是 agent
分流的範疇，線上實際會選 `get_rag_answer`。

正樣本漏掉一則（TFC 查過但驗證器判為不同主張）——fail-closed 的代價，25% 的召回
損失換 55 個百分點的誤配下降。

## 這份量測的已知限制

**正樣本的 60 題是 LLM 自動改寫、未經人工複核。** 其中可能混入不是主張的句子
（例如「那有沒有什麼方法可以趕快增強免疫力？」是追問而非可查核主張），會讓 78%
這個數字偏低。

golden set 的 9 題是人工逐題撰寫並確認為清楚單一主張，`--with-verdict` 量出 100%。
兩個數字的落差**最可能是題目品質而非難度**——要真正比較，得先審過那 60 題的文字
品質，不能直接對照兩個數字。

樣本數也小（正樣本 60、負樣本 20、golden 9/8），只夠支撐「方向」而非精確值。
