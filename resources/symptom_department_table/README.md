# 症狀科別對照表：新醫院資料併入 SOP

收到新醫院公開的「症狀／疾病 → 看哪一科」資料時，AI 助理與維護者照這份流程併入 `symptom_department_reference.json`。流程的重點是**每一步都由人裁決**：AI 負責抓錯字、對應科別、提出疑點與算出清單，要收什麼、不收什麼由人決定。

## 相關檔案

| 檔案 | 用途 |
|---|---|
| `symptom_department_reference.json` | 對照表本體。`sources` 登記來源醫院，`departments[].symptoms[]` 是條目，`excluded` 記錄不收的項目，`resolved_questions` 記錄裁決 |
| `symptom_vectors.json` | 條目名稱的向量索引，由 `scripts/build_symptom_vectors.py` 產生 |
| `app/services/medical/symptom_classification/symptom_table.py` | `load_symptom_table()`：載入時驗證格式，任何一項不合就拋錯 |
| `app/services/medical/department_matcher.py` | `resolve_department()` 與 `CANONICAL_DEPARTMENTS`（部定專科，目前 42 個） |
| `tests/unit/services/medical/test_symptom_acceptance.py` 等三個測試檔 | 讀真表的驗收測試，見階段 4 |

## 四階段流程

### 階段 1：閱讀、校字、科別對應

1. **來源代碼**
   - 先查 JSON 的 `planned_sources` 是否已預留這家醫院，有就沿用並搬進 `sources`。
   - 沒有預留時，依「醫院縮寫_院區」格式提出代號給人決定（例：`TPVGH_HC`、`CMUH_HC`、`TZUCHI_HL`）。避免與既有代碼太像。
   - 同一家醫院網站分好幾個頁籤（內科系、外科系…）時沿用同一個代碼，只補條目。
   - 元資料填 `name`、`url`、`site_updated`、`retrieved_at`、`level`。`level` 程式不讀，不確定就填 `null`，不要猜。
2. **錯字、舊字、亂碼**
   - 校正錯字與舊用語（高低血納 → 高／低血鈉、老人痴呆 → 失智症、廔管 → 瘻管），原文記進條目的 `note`。
   - Big5 亂碼（例：「腎弁鉦妤`」，許功蓋問題）與截斷的文字，列出來請人對照原網頁，無法確認就不收。
   - 醫院網站常擋爬蟲，原文以使用者貼上的為準。
3. **科別對應**
   - `canonical` 必須能被 `resolve_department()` 解析，且表內已有該科別區塊。表內沒有的科別要新增區塊，需要 `db_facility_count`（查資料庫）。
   - 資料庫院所數少於 10 家的科別，併入母科別，條目寫 `downgraded_from`，並更新 `downgrade_rule.applied`。
   - `subgroup` 是卡片上顯示的掛號診名，必須以「科」結尾。新條目沿用表內已統一的名稱（見「已定案的規則」），不照抄該院的診名。
   - 門診名稱不以「科」結尾時（運動傷害門診、足踝特別門診）`subgroup` 留空。

### 階段 2：疑點討論

AI 主動列出下列幾類，附建議，由人裁決。已有先例的直接比照並說明依據：

- **不符就醫直覺的科別**：例如心臟血管外科列高血壓、胸悶；身心科列胃痛；過敏免疫風濕科列發燒、口腔潰瘍。
- **急症**：由 `urgency.py` 的判斷器短路處理，不收。
- **非症狀項目**：體檢、篩檢、服務、手術、治療、美容。
- **籠統描述**：各種肺部疾病、老化、一般眼疾、心理困擾這類類別描述。
- **同義詞**：要併入既有條目還是另立新條目。
- **候選數**：會讓某個症狀到達或超過 5 個科別的新增（見「候選上限」）。
- **次專科不一致**：新來源把既有條目列在不同專科時，要不要把專科加進 `subgroup`。

### 階段 3：清單確認

- 用腳本拿真表比對，產出完整清單：依 `canonical` 分組，每條標出「補代碼」（既有條目追加來源代碼）、「補代碼並擴充 subgroup」或「新增」，並列出不收的項目與原因。
- 數字一律用腳本算，不要手算。
- **停下來等人明確說「可以寫入」**，未獲同意不得寫入 JSON。

### 階段 4：寫入與測試

1. **寫入前**確認工作區狀態：使用者可能在 IDE 手改過 JSON，或已經 commit。寫入腳本通常不能重複執行。
2. **寫入**
   - 登記 `sources`，`version` 加 1，更新 `generated_at`。
   - 補代碼或新增條目；改寫過名稱的新條目在 `note` 記 `「代碼 原文：…」`。
   - 不收的項目依科別分組寫進 `excluded`（`raw`、`source`、`reason`）。
   - 這次新定的規則寫進 `resolved_questions`（`question`、`decision`、`rationale`、`decided_at`）。
   - `planned_sources` 是手工排版（一行一家），用 `json.dumps` 重寫整份檔案時要保留這段原排版。
3. **載入測試**：執行 `load_symptom_table()`。常見失敗是同一科出現兩筆同名條目（例：手動把「蜂窩組織炎」改名成既有的「蜂窩性組織炎」），應合併成一筆。
4. **跑讀真表的測試**，照新資料更新預期值：
   - `tests/unit/services/medical/test_symptom_acceptance.py`
   - `tests/unit/services/medical/test_symptom_department_service.py`
   - `tests/unit/services/medical/test_symptom_vector_index.py`（向量未重建前必定失敗）

   `test_symptom_acceptance.py` 檔頭規定期望值有誤要先回報、由人決定。除了家數與排序的機械性更新，換掉測試用的範例詞（例：尿床改用生長發育遲緩）或反轉驗收語意時，必須明確告知。
5. **向量索引與 commit**
   - 連續匯入多家時可以先不重建向量；比對層會退回 LLM 全表挑選，功能不會壞。
   - 匯入告一段落就執行 `python scripts/build_symptom_vectors.py`。
   - **重建後抽查常見說法的第一名**：新增的長條目可能搶走短詞比對。例：「帶狀皰疹疼痛」對「帶狀皰疹」0.969，蓋過了正確條目。
   - commit 由使用者決定時機。

## 已定案的規則

### 不收

| 類別 | 規則與例子 |
|---|---|
| 體檢、篩檢、服務、處置 | 新併入來源不收 `screening`／`service`／`procedure`；表內舊有的這類條目暫不回溯清理。例外：高危險妊娠（孕婦能自行辨認的狀況）照收 |
| 手術、治療、矯正、重建 | 「XX手術」「XX治療」整項不收，**不抽取疾病名**（白內障手術、發炎性腸炎治療皆不收） |
| 標題在手術或治療之下 | 標題是手術、治療、美容時，底下列的病名也不收（甲狀腺手術項下的甲狀腺腫瘤、雷射治療項下的曬斑） |
| 急症 | 休克、顱內出血、呼吸衰竭、急性中毒、消化道出血、心肌梗塞等不收；自殺相關依 2026-09-02 決議交一般流程。症狀層級的昏倒、咳血、吐血、胸痛、氣胸、胸部外傷照收，由判斷器依整句判斷 |
| 美容 | 醫學美容門診、光電雷射、肉毒、皺紋、美白不收；雀斑、肝斑、曬斑、黑斑等色素問題照收 |
| 籠統描述 | 類別描述而非具體症狀 |
| 脫離上下文即過度導向 | 來源只把常見症狀當成特定疾病的例子時，不拆成通用推薦。例：血液腫瘤科「凝血異常如牙齦出血」「骨髓病變如背痛」；腎臟內科裸列「腰痛」也不收，因缺少血尿、排尿異常等能區分腎臟問題的線索 |
| 認定、申請、諮詢 | 職業傷病認定、勞保補助、癌症諮詢等不收 |

### 收

- 「XX的診治、診療、診斷及治療、控制、監控、處理、評估」拆出疾病或症狀收錄（肺癌診治 → 肺癌、三高的監控 → 高血壓／高血脂／糖尿病）。只有「治療」「手術」整項不收。

### 候選上限

- 一個症狀超過 5 個科別（`MAX_CANDIDATES`）就走保底，所以**已達 5 科的症狀不再加新科別**（例如中醫部的腹痛不收）。麻醉疼痛科的腰痛雖在移除腎臟內科後只剩 4 科，仍因屬高度專門治療路徑而不作為一般初診候選。
- 合寫的症狀不要併進已達上限的條目：「腰痛背痛」拆成腰痛、背痛，不併入已有 5 科的腰酸背痛。
- 「頭痛」目前已有 5 科，不再替它加科別。
- 新增會讓某症狀成為**唯一候選**且不合常理時不收（中醫部、身心科的胃痛）。

### 補代碼與 subgroup

- 症狀在該科已有條目就補代碼，沒有才新增。
- 新來源把既有條目列在不同專科時，照樣補代碼，並把該專科加進 `subgroup` 陣列（例：腹水加胃腸肝膽科）。專科明顯怪的逐案提出，例如國軍桃園的倦怠（腸胃內科）、疝氣（小兒外科）就不收。
- 既有條目 `subgroup` 為空時只補代碼，不填入。
- 已統一的次專科名稱：新陳代謝及內分泌科、免疫風濕科、心臟外科、乳房外科（「甲狀腺結節」例外，列一般外科）。血液科與血液腫瘤科刻意維持兩種。

### 同義詞

- 只有醫學上確為同一件事才合併，不確定就各自新增。
- **不合併**的先例：XX癌 ≠ XX腫瘤、消化道潰瘍 ≠ 消化性潰瘍、老人跌倒 ≠ 反覆跌倒、接觸性疾病 ≠ 性病；泌尿科列的「不孕症」不併入男性不孕症（原文未指明性別）。
- **全表統一**的條目名稱，之後的醫院一律補在這些條目：
  - 血便（便血併入）
  - 帶狀皰疹（皮蛇、飛蛇）（飛蛇、皮蛇、帶狀皰疹、帶狀皰疹疼痛併入）。只寫俗名時，打「帶狀皰疹」的向量分數低於比對門檻
  - 昏倒（昏厥併入）
  - 大腸癌（大腸直腸癌併入）
- 條目名稱同時是卡片顯示文字與向量比對的來源。改名前可以先用 embedding 實測各種說法的分數：≥ 0.95 直接命中，0.87～0.95 交 LLM 決選，< 0.87 對不到。

### 兒童相關

- 兒科過濾只排除「兒科」。`subgroup` 是兒童青少年精神科的候選，成人也會拿到，所以兒童少年門診列的「夜尿」不收（否則成人問尿床會拿到兒童青少年精神科）。
- 兒科年齡界線採 15 歲以下，此界線為專案自訂。

## 已知待辦（全部醫院匯入後再處理）

- 兒科過濾要一併排除兒童青少年精神科的候選。
- 多個常見症狀已到 5 科上限（腹痛、血尿、頻尿、性病、坐骨神經痛、腰酸背痛、便秘、咳嗽、腹瀉、頭暈），需重新檢討 `MAX_CANDIDATES`。腰痛與背痛於 2026-09-20 移除失去上下文的專科關聯後，各剩 4 科。
- 同家數時排序比院所數，中醫一般科有 4172 家，幾乎必排在西醫科前面（例：經痛先中醫後婦產科）。2026-09-17 決定暫維持現狀。
- 掃描同一件事的重複條目：高血脂／高血脂症、骨質疏鬆／骨質疏鬆症、類風濕關節炎／類風濕性關節炎、隱睪／隱睪症、尿路感染／泌尿道感染、神經科「頭晕」（簡體字）。

## 新對話的開頭提示詞

> 請遵循 CARE 專案 `resources/symptom_department_table/README.md` 的「新醫院資料併入 SOP」，協助我處理接下來提供的醫院資料。先讀完該文件與 `symptom_department_reference.json` 的 `sources`、`planned_sources`、`resolved_questions`，再依序執行：
>
> 1. 閱讀我給的網址與文字，提出來源代碼，列出錯字、舊字、亂碼，說明科別如何對應 `canonical` 與 `subgroup`。
> 2. 提出可疑或值得討論的地方（不符直覺的科別、急症、非症狀項目、籠統描述、同義詞、候選上限、次專科不一致），已有先例的比照並說明。
> 3. 依我的裁決，用腳本比對真表，列出完整清單後停下來，等我說「可以寫入」。
> 4. 寫入 JSON、執行 `load_symptom_table()` 與讀真表的測試並更新預期值。我表示還有醫院要匯入時先不重建向量索引；commit 等我開口。
>
> 理解的話請回覆「已準備就緒，請提供新醫院的資料或網址！」。
